# Docs

One folder per line of thought. Read in this order.

| Folder | Holds | Files, in reading order |
|---|---|---|
| `project/` | What we are doing | `problem.md` (the problem, defined), `question.md` (the question and the hypotheses), `evaluation.md` (how results are measured, compared and judged), `design.md` (models, methods, experiments, phases), `data.md` (what text is used for what), `project.md` (scope, timeline, open questions) |
| `concepts/` | What we must understand | `quantization.md` (PTQ in plain language), `explanations.md` (the candidate explanations E1–E7), `literature.md` (what is known, what nobody measured), `research.md` (research vs development, kinds of project, human evaluation) |
| `papers/` | The PDFs in `../papers/` | `index.md` first; the rest are one entry per paper, by theme, lookup only |
| `workflow/` | How we work | `conventions.md` (code, tests, results, docs), `cluster.md` (BYU cluster), `BYU_ORC_AGENTS.md` (verbatim policy), `progress.md` (dated record, history only), `hours.csv` (work sessions: start, end, hours, category) |
| `proposal/` | The proposal | `proposal_draft.md` (first draft), `698R_Proposal_Form.pdf` (the form) |

Start with `project/problem.md`, then `project/project.md`, then `concepts/quantization.md`,
then `concepts/explanations.md`, then `project/design.md`.
